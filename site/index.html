Open Forward Reviews

Realistic requests that do not say what to do, put to the same agent with and without its tooling. What changes — the answer, or what it costs to reach it?

Review this TYPO3 extension and tell me what needs attention.
Editors report that saving a translation in the TextDb backend module does nothing — the dialog closes, but the old value is still there. Please find out what is going on.

The setup

A real TYPO3 extension, frozen at one historical commit. The agent receives the single sentence above and nothing else: no framework version, no tool to run, no file to open, no category of finding to produce. Working that out is what is being measured.

Four configurations, three runs each. Everything is held constant except the skills: same repository, same commit, same model (Claude Code on claude-opus-5), same grader, same environment, same trial count.

controlClaude Code on its own
nrplus eight Netresearch skills, pinned to released versions
companionplus the TYPO3 Dev Companion: twelve skills and its MCP server
nr + companionboth stacks at once

Grading does not ask "did it find the expected bugs" — an open question has no fixed answer key. It asks how the work was done, across eight aspects: did it establish what the project is; did it reach a systematic route; did each claim come from the source that owns that fact; are findings anchored to a place and a consequence; were the available checks actually run; is the most important thing first; did it assert anything it never established; and could a developer act on the result.

A factor of six separates the cheapest configuration from the dearest, and nearly four in wall time. The Netresearch stack is the cheapest of the four: 2.4× cheaper than the unaided agent and 5.4× cheaper than the companion.

Medians of three are a weak instrument, so the individual runs decide whether this holds. Here they do: the Netresearch runs cost $0.81, $0.91 and $2.04, the unaided runs $2.15, $2.16 and $2.26. The ranges do not overlap — the dearest run of the cheaper configuration is still cheaper than the cheapest run of the other. The companion's runs, $4.07 to $6.17, sit entirely above both.

All four produce equally usable reviews

Outcome quality is 3/3 everywhere, and six of the eight dimensions are flat across the four configurations. On this case, what a developer receives does not depend on which stack produced it. What differs is the effort spent reaching it.

Routing separates, but partly by construction

Skill routing is the one large gap, and the weakest evidence in the table: control has no injected skills, so there is less to route to. It is not entirely definitional — the grader counted Claude Code's own entry points as available and scored their non-use as a routing failure — but it should not be read as a quality difference.

Two dimensions stay weak everywhere

No configuration reaches source authority reliably. In all twelve runs the mechanical evidence says the same thing: no external canonical source consulted, the resolved dependency state never read. Every statement about framework version support rests on recollection rather than a lookup, and a version constraint states what is permitted, not what is installed or tested.

Unsupported claims is weakest with the Netresearch stack alone (0/3) and strongest with both stacks together (2/3, 0.89) — better than either alone. On this case the two compose rather than collide.

The most expensive configuration buys the least

Both stacks together cost six times what the Netresearch stack alone costs, and reach no dimension it does not, apart from unsupported claims.

What this does not show. One case, one agent, one model, three runs per configuration. This is one measurement, not a verdict on any stack. Differences of a single run are within noise, which is why counts are reported instead of averages.

Case 2 — a runtime bug. Result: nothing the tooling offered was taken up

The second case does not review a checkout. It runs an installed TYPO3 13.4 with the extension active and a database in the state a real production report described: saving a translation silently writes an orphaned row instead of updating, and every later save then collides with a unique key. The first failed save shows no error at all.

Five configurations this time, three runs each, everything else held constant. The fifth is the Netresearch setup as actually deployed — twelve skills and the command-line toolchain those skills instruct (ripgrep, fd, jq, yq, dasel, ast-grep and more), installed where only that configuration can reach them.

Every configuration solved the case, and every one solved it the same way. All fifteen runs reached the top mark for identifying the mechanism: the extension's domain models declare their persisted properties private, which Extbase cannot reach from the parent class, so the references a save should carry are never resolved. The agents did not read that off the source — they ran the repository call inside the framework's bootstrap, produced the error, applied the change provisionally, re-ran the save path, read the written row back out of the database and reverted. The fix that shipped changes exactly those properties.

The fullest configuration scores identically to the bare agent on all eight dimensions, met-count for met-count. And across all fifteen runs not one skill was invoked — with eight available, with twelve, with twelve plus a toolchain. In the nr-full runs not one of the nine installed commands was used either, in 54 to 83 tool calls apiece.

A configuration nobody used and one nobody could reach produce the same zero, so the mechanism was checked before the behaviour was reported: in a container with that configuration's own PATH, inside the agent's shell, command -v rg answers /opt/nr-toolchain/bin/rg. The tools were reachable.

Unlike case 1, the cost figures here do not separate the configurations. The spread inside each one swallows the difference between them — the unaided agent alone ranges from $2.99 to $8.21 on identical inputs. Where case 1 showed non-overlapping ranges, this case shows overlapping ones, and no cost claim is made from it.

What follows from this. An agent that can already finish a task does not go looking for help with it; skills and tools are offers, and an offer is taken up by an agent that needs it. Both of these cases sit at the ceiling — in the upgrade case the unaided agent widened the version constraints and passed 719 tests on both framework lines at the first attempt. That makes them poor instruments for what tooling is worth and good instruments for something else: what carrying the tooling costs when it goes unused. Measuring the benefit needs tasks the unaided agent does not finish.

What the agents actually found

Every configuration produced a substantive review. The leading finding in the unaided run was a cache-clearing middleware registered in the frontend stack that never checks whether a user is authenticated — anchored to file and line, with the consequence stated: any anonymous visitor can flush page caches. Neither that nor two further findings appear in the case's recorded background notes; the agent established them from the code.

The reviewed commit also carries three security findings marked with inline suppression comments. A static analysis run reports clean there while the problems remain, which is what lets the case distinguish an agent that reads a green result as reassurance from one that asks what produced it.

Correction, 17 August 2026 — case 1. An earlier version of this page reported that the Netresearch stack improved prioritization from 0.61 to 0.94 and called the difference real. It was not. Nine grading criteria had hit a judge timeout, and the grading harness records a timed-out judge as zero. Re-scored without the timeout, the control configuration reaches 0.94 as well and the difference disappears. Its unsupported-claims figure was reported as 0.50 and is 0.72. Six such instrument failures were found and fixed while producing this table, every one returning a plausible number rather than an error; they are listed in docs/instrument-failures.md.

Method

27graded runs across two cases
8graded dimensions per run
8instrument failures found and fixed

Execution, isolation, skill injection, trajectory recording and regrading are provided by Harbor. This project contributes the review methodology, the cases, the eight-dimension rubric and the conventions that keep results comparable. Grading rests on observable behaviour only — tool calls, commands, files opened, output seen, the resulting diff and the final answer. Stated intentions are not evidence, and private reasoning is never read.

The agent cannot reach the reviewed repository's own forge during a run: the working copy is a single-commit fetch with the remote removed, and the network allowlist excludes it while still permitting the framework's canonical documentation. The later change that fixed several of the issues lives in that repository's future and stays out of reach.
