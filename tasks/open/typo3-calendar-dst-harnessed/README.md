# OFR-TYPO3-CALENDAR-001-HARNESSED — the same bug, in a repository made agent-ready

The experiment this benchmark was built for, and had never run. Ten of eleven
cases vary the *fleet* — the skills an agent carries. The thesis is about making
a *repository* agent-ready. Here the fleet is held constant and the repository
is the variable.

| | vanilla | harnessed |
|---|---|---|
| **fixed it (mechanical, no judge)** | **2/12** | **2/12** |
| Wilson interval | [0.05, 0.45] | [0.05, 0.45] |
| Fisher exact p | — | 1.000 |
| the check it ran could have failed | 2/12 | 1/12 |
| claims match what was shown | 5/12 | 5/12 |
| established the defect before changing it | 1/12 | 1/12 |
| the change is narrow | 8/12 | 10/12 |

At six trials a side this read 2/6 against 1/6, and `scripts/compare` said what
that was worth: *"a one-trial difference is within the noise of a stochastic
agent."* Doubling both sides dissolved it — the two arms are now identical on
every line that matters. The first reading was noise, and the tool called it
before the second series existed.

**What twelve a side does and does not license.** It does not establish that the
treatment has no effect; the Wilson interval puts both true rates somewhere
between 5% and 45%, which excludes a large effect and leaves a moderate one
possible. What it does establish is that nothing was observed, on this defect,
with this model, at a sample size twice what the first claim rested on.

## The treatment, and that it arrived

Eighteen files generated by `netresearch/agent-rules` from this repository at
this commit — a root `AGENTS.md`, five scoped ones, their `CLAUDE.md` and
`GEMINI.md` symlinks — frozen into `environment/harness/` and applied at build
time. Nothing else differs from the vanilla variant, and the build asserts it.

**Five of six trials read it**, mentioning `AGENTS.md` between 3 and 43 times.
That distinguishes this experiment from every skill measurement here: a skill is
loaded in 0 of 6 trials on this case, so those comparisons measured the base
model twice. This one did not. The intervention reached the agent and can be
judged on its merits.

## What it did not do

**It did not make the work come out better.** One fewer fix, which at six trials
a side is nothing either way.

**It did not fix the failure it explicitly addresses.** The generated
`AGENTS.md` carries this, in its Workflow section:

> *Before claiming done: Run verification and **show output as evidence** —
> never say "try again", "should work now", "tested", "verified", or "all
> green" without pasted command output in the same turn.*

That is precisely the behaviour the vanilla arm fails at. After the treatment,
`the_check_it_ran_could_have_failed` is met in **0 of 6** trials, against 2 of 6
before. And the command table names the functional-test invocation that would
have shown a wrong fix failing — used in **2 of 6** trials.

So the document was read and not followed. That is the same pattern the skill
measurements produced at the level of skill instructions, now observed one level
down, on a document the agent demonstrably opened.

## What this does not license

One task, six trials a side, one model. Nothing here says a harness is
worthless: it says that on this defect, with this generated harness, the work
did not come out better and the specific instruction most relevant to the
failure was not acted on. A second task would be the first thing to spend on,
and `docs/composition-sweep.md` is the wrong place to look for a mechanism —
this is not about routing.

## Reproducing

```
scripts/run-evaluation OFR-TYPO3-CALENDAR-001           --fleet control --trials 6 --model claude-haiku-4-5-20251001
scripts/run-evaluation OFR-TYPO3-CALENDAR-001-HARNESSED --fleet control --trials 6 --model claude-haiku-4-5-20251001
scripts/compare --variable repository <vanilla-job> <harnessed-job>
```

Both arms must be run under the same task digests as each other; the vanilla
case declared its variant only after its first fleet comparison, so the earlier
vanilla jobs belong to a different digest and are not part of this pair.
